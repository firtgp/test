# Сайт модового Minecraft-проекта

Публичный сайт, кабинет игрока с магазином и админка для проекта из нескольких серверов на модовых сборках.
Название, серверы, сборки, моды, новости, правила, ссылки и медиа меняются в админке, без нового деплоя.

> NOT AN OFFICIAL MINECRAFT SERVICE. NOT APPROVED BY OR ASSOCIATED WITH MOJANG OR MICROSOFT.

## Что внутри

| Часть | Где | Что делает |
|---|---|---|
| Сайт | `src/` | React 19, Vite, React Router, Astryx, Phosphor Icons, TanStack Query, Zod |
| База и права | `supabase/migrations/` | Таблицы, RLS, серверные функции (ник, роли, баны, правила, сессии лаунчера, кошелёк, покупки, очередь выдачи) |
| Стартовое содержимое | `src/data/seed.ts` → `supabase/seed.sql` | Пример серверов, сборок, новостей и правил |
| Авторизация лаунчера | `supabase/functions/launcher-auth/` | Вход по нику и паролю, `join`, `has-joined` |
| Магазин: сервер | `supabase/functions/shop/` | Очередь выдачи для игровых серверов и приём подтверждения оплаты (шаблон под провайдера) |
| Кабинет игрока | `src/pages/account/` | Обзор с 3D-персонажем, магазин, ранги, баланс, настройки |
| Мониторинг | `worker/` | Опрос серверов по Server List Ping и запись снимков в БД |
| Проверки | `tests/`, `e2e/` | SQL-гарантии, модульные и сквозные тесты |

Состав — PLAYER_CORE (витрина, аккаунт игрока, админка) и SHOP: каталог предметов и рангов, внутренняя
валюта, заказы и очередь выдачи. Оплата реальными деньгами не подключена: платёжный провайдер не выбран,
для него оставлен шаблон обработчика. Скины, банлист, голосования, вики, тикеты, статистика, AI и PWA не включены.

### Кабинет игрока

| Раздел | Адрес | Что в нём |
|---|---|---|
| Обзор | `/account` | Трёхмерный персонаж (вращается мышью, пальцем и стрелками), четыре образа, баланс, ранг, сервер |
| Магазин | `/account/shop` | Предметы из модов разных серверов, фильтр по серверу, покупка с подтверждением |
| Ранги | `/account/ranks` | Три ранга на 30 дней; ранг меняет пьедестал и ауру персонажа на сайте |
| Баланс | `/account/wallet` | Внутренняя валюта, пополнение, заказы и история операций |
| Настройки | `/account/settings` | Профиль, сервер по умолчанию, ник, пароль, активные сессии |

Образ персонажа — модель из блоков, собранная кодом. Игровой скин она не меняет: загрузка скинов (SKINS) не включена.

## Запуск

```bash
pnpm install
pnpm dev          # http://127.0.0.1:5173
```

Без переменных `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` сайт работает в **демо-режиме**: данные лежат
в браузере, письма не отправляются, наверху стоит пометка. Вход в демо-админку: `owner@example.org` /
`demo-owner-pass`. Демо-игрок с балансом: кнопка «Войти как демо-игрок» на странице входа или «Открыть
демо-кабинет» на главной (`player@example.org` / `demo-player-pass`). В демо баланс пополняется без денег,
а купленное в игру не выдаётся: игровой сервер не подключён. Демо-режим не даёт серверных гарантий и не
предназначен для публикации.

Поставить демо на чистый VPS (Debian или Ubuntu) одной командой от root:

```bash
curl -fsSL https://raw.githubusercontent.com/firtgp/test/claude/skill-uiux-pro-max-v7xtyn/deploy/install.sh | bash
```

Скрипт ставит nginx и Node.js, собирает сайт и публикует его на порту 80. Повторный запуск обновляет сайт.

## Рабочий режим (Supabase)

1. Создайте проект Supabase и примените миграции и seed:
   ```bash
   supabase link --project-ref <ref>
   supabase db push
   psql "$DATABASE_URL" -f supabase/seed.sql   # по желанию: содержимое-пример
   ```
2. В Auth включите подтверждение почты и добавьте адрес сайта в Redirect URLs (`/login`, `/reset`).
   Минимальную длину пароля поставьте 10.
3. Разверните функции и задайте секреты:
   ```bash
   supabase functions deploy launcher-auth --no-verify-jwt
   supabase functions deploy shop --no-verify-jwt
   supabase secrets set GAME_SERVER_KEY=<длинная случайная строка>
   supabase secrets set PAYMENT_WEBHOOK_SECRET=<секрет подписи webhook вашего провайдера>
   ```
   В `supabase/functions/shop/index.ts` проверка подписи и разбор тела webhook — шаблон: замените их по
   документации выбранного платёжного провайдера. Пока провайдер не подключён, раздел «Баланс» прямо
   сообщает, что пополнение недоступно; начислить валюту может владелец функцией `grant_currency`.
4. Скопируйте `.env.example` в `.env`, заполните `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`, соберите:
   ```bash
   pnpm build      # статика в dist/
   ```
   Статику можно разместить на Vercel или Cloudflare Pages. Нужен fallback всех путей на `index.html`.
5. Запустите воркер мониторинга на сервере с исходящим TCP (VPS рядом с игровыми серверами):
   ```bash
   SUPABASE_URL=... SUPABASE_SERVICE_ROLE_KEY=... pnpm worker:monitor
   ```
6. Зарегистрируйтесь на сайте и выдайте себе роль владельца один раз через SQL:
   ```sql
   insert into public.staff_roles (user_id, role)
   select id, 'owner' from public.profiles where nick_norm = lower('ВашНик');
   ```
   Дальше роли выдаются в админке.

Service-ключ, `GAME_SERVER_KEY`, секрет webhook и пароль RCON никогда не попадают во frontend: в сборку
идут только переменные с префиксом `VITE_`.

## Проверки

```bash
pnpm typecheck
pnpm test         # модульные: Server List Ping на поддельном сервере, статусы, правила покупки в демо
pnpm test:sql     # миграции + seed на временном PostgreSQL: ник, роли, кошелёк, покупки, очередь выдачи
pnpm e2e --trace off      # сквозные сценарии в браузере (демо-режим)
```

`pnpm test:sql` требует локальный PostgreSQL 14+ (`initdb`, `pg_ctl`, `psql`). Он использует
`tests/sql/shim.sql` — минимальную имитацию ролей и схем Supabase.

## Перед запуском замените

- Название проекта, заголовок, ссылки на лаунчер и сообщество — «Админка → Настройки».
- Серверы, адреса, сборки, списки модов — они условные. Версии и лицензии модов не заполнены намеренно.
- Сцены первого экрана и картинки в остальных блоках главной — это иллюстрации из блоков, собранные кодом
  (`src/scenes/worlds.ts`), а не скриншоты ваших миров. Макет лаунчера в блоке «Четыре шага» — схема. Сцену для сервера выбирают в «Админка → Серверы → Сцена на главной».
- Правила — в seed лежит пример.
- Каталог магазина — пример (`src/data/shopSeed.ts`): названия, цены и бонусы рангов условные. Перед
  подключением оплаты сверьте каждый товар с действующими правилами Mojang для серверов (раздел «Servers
  and hosting» в Minecraft Usage Guidelines): продажа предметов и рангов, влияющих на игру, может их
  нарушать. В админке у товара есть отметка проверки. Плащи и азартные механики не продаются.
- Название внутренней валюты и её формы — «Админка → Настройки».
- Юридические тексты (оферта, возраст, возвраты) не написаны: их готовит владелец по своей юрисдикции.
